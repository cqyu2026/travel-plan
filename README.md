# travel-plan

中文旅行规划与手机手册 Skill，当前版本 **0.1.2 流程修订版（2026-09-20）**。

从出游需求开始，逐步形成可讨论的旅行计划；计划确认后整理交通、酒店、门票和预约待办，同时生成可离线阅读的单文件 HTML 旅行手册；再根据订单与攻略核验、调整安排并同步更新手册，按需部署和后续更新。

## 文件

- [`travel-plan/SKILL.md`](travel-plan/SKILL.md)：技能入口、规划流程和订单核验规则。
- [`travel-plan/references/web-handbook.md`](travel-plan/references/web-handbook.md)：网页制作、隐私、交接、部署和验证要求。
- [`travel-plan/assets/travel-handoff.md`](travel-plan/assets/travel-handoff.md)：跨平台接续模板。
- [`travel-plan.zip`](travel-plan.zip)：仅含上述三个技能文件的导入包。

## 使用

将下面的提示词发送给 Codex，让它从 GitHub 安装技能：

```text
请从这个 GitHub 仓库安装 travel-plan 技能：
https://github.com/cqyu2026/travel-plan

技能位于仓库的 travel-plan/ 目录。请安装完整目录，保留 SKILL.md、references/ 和 assets/ 的结构，
不要只安装入口文件。安装完成后检查文件和引用是否完整，并告诉我如何开始使用。
```

技能可供 Codex 与 WorkBuddy 按实际环境能力执行。下面的模板可直接复制，将方括号替换为自己的信息；尚未确定的字段可以留空，已有信息无需重复填写。订单截图、计划和 HTML 需实际附上，或提供当前工具可读取的文件位置。

## 使用流程与提示词模板

**收集需求 → 初步规划 → 调整并确认 → 购买预约清单 + 首版手册 → 自行购买预约 → 订单核验与手册更新 → 按需首次发布 → 后续同步更新。**

已有计划或订单时直接从对应步骤开始。完整流程中，确认计划后默认生成手册；用户明确只要规划、清单或审核时，按限定范围交付。

### 1. 开始规划

提供已确定的条件，先讨论路线、住宿区域与时间安排，不需要先买齐订单。

```text
用 travel-plan 帮我规划一次旅行。

出发地：[城市]
目的地：[城市或区域]
出游时间：[完整年份、日期范围或天数]
出游人数：[成人与儿童人数，儿童年龄]
大交通方式：[自驾 / 高铁 / 飞机 / 尚未确定]
必去景点：[地点]
需求：[预算、午休、少换乘、停车等，以及最优先的需求]

先给我一份可以讨论的完整计划，说明主要取舍和待核实事项。
暂时不生成购买预约清单和网页，等我确认计划。
```

### 2. 调整并确认计划

讨论阶段可以只调整局部，不必重新填写需求。涉及必去项目、已购安排或跨日变化时，会说明影响后再确认。

```text
请调整刚才的计划：[具体修改，例如第二天下午留出两小时午休]。
保留：[必去项目或已确认安排]。
先说明影响和建议，不要把尚未确认的替代方案写进已确认行程。
```

满意后发送：

```text
我确认当前这版计划，采用[方案名称；只有一个方案时可省略]。
请列出购买与预约清单，同时生成首版 index.html 旅行手册。
保留未购买、未预约和待核实状态，不等待订单齐全。
目前不公开发布，先交付可保存、可离线阅读的 HTML。
```

此时应得到购买预约清单和实际 HTML 文件。购买、付款和预约由用户自行完成。

### 3. 提供订单，核验并更新手册

附上订单截图、票据或文字信息；连续发送多份资料时，可以先说明“等我发完再集中核对”。

```text
用 travel-plan 接续当前计划。我已附上[交通 / 酒店 / 门票 / 预约]资料。
资料已发完，请提取订单事实，检查时间冲突、接驳缓冲和预约条件。

已完成：[已购买或已预约的事项]
尚未完成：[待购买或待预约的事项]
最新更正：[如有改签、取消或旧凭证失效，在这里说明]

请更新行程、剩余待办和现有旅行手册。
已完成的购买或预约从对应待办中移除，确认信息融合进逐日行程；
未完成的预约、退款和核验继续保留。
涉及必去项目或已购安排的实质取舍，先交我确认。
已有公开页面时，同步更新本地文件和原公开页面。
```

### 4. 首次发布，分享给同行人

首次公开发布需要明确提出。已有域名时，提供托管方式；无域名时，按既定流程由 WorkBuddy 发布。在其他环境无法直接完成时，先交付 HTML 和自包含的交接材料。

```text
请将当前确认的旅行手册公开发布，供同行人通过手机链接查看。

现有 HTML：[附件或文件位置]
域名与托管：[无自有域名，由 WorkBuddy 发布 / 指定域名、托管平台及现有部署方式]

请检查公开内容不含敏感订单信息，完成后返回可保存的 HTML 和真实公开网址，
并验证未登录访问、手机布局和当前行程内容。
如果需要我操作，请一次列清必要步骤，不要把未完成的发布报告为成功。
```

不要在提示词中填写密码、密钥或证件号。公开发布前需具备对应工具、账号权限和托管条件。

### 5. 出行前或途中修改

已有公开页面默认随本地文件一起更新，无需每次重新要求同步。修改后分别报告本地和线上实际更新结果；能力或权限受阻时，说明尚未完成的部分。

```text
用 travel-plan 更新这次旅行。

最新变化：[新班次、预约结果、取消事项或其他变更]
现有手册：[附件或文件位置；当前任务已有则省略]
现有公开网址：[网址；当前任务已知则省略]

请复核受影响的安排，更新逐日行程、订单信息和剩余待办，
并同步更新本地 HTML 与原公开页面，清除失效信息。
需要我决定的实质取舍先说明，其余可确定的事实和状态先更新。
```

如果本次只想修改本地版本，在请求中补充：

```text
本次只更新本地 HTML，不同步到公开页面。
```

### 其他常用范围

**只核验订单：**

```text
用 travel-plan 只审核这些订单与当前计划。
请区分硬冲突、缓冲不足、待核实和舒适度建议，给出依据与调整建议。
本次不修改手册，也不更新公开页面。
```

**只制作简版离线手册：**

```text
用 travel-plan 按已确认计划生成简版离线 HTML。
保留逐日行程、订单状态和必要待办，不需要天气和地图。
本次不公开发布，也不更新已有公开页面。
```

**换任务或跨平台接续：**

```text
用 travel-plan 从当前阶段继续，不重新开始规划。
我已附上最新旅行手册和接续资料。
当前阶段：[计划已确认 / 等待预约 / 已发布后修改]
本次需要：[具体任务]
最新更正：[如有]
现有公开网址：[如有]
请先读取已有信息，只追问影响本次任务的关键缺口。
```

## 主要边界

- 初步规划不要求订单齐全，已有计划和订单从当前阶段接续。
- 购票、预约、核验与模拟标记分别保留；已购门票不等于已预约演出。
- 动态信息需查证适用日期，来源冲突或缺少依据时保留待核实。
- 不自动购票、付款、预约或创建监控。
- 公开 HTML、离线交付和交接材料不包含原始订单、确认号、证件号、二维码或私人联系方式。
- 新建与更新网页先检查已有文件，正文不依赖外部资源；天气和导航属于联网增强。

网页默认依次展示此刻关注、目的地当天天气与体感温度、总览地图、出行前待订购与预约、逐日行程、其他待办与贴士。此刻关注保持原样；完成购票或预约后移除对应待办，确认信息融合到逐日行程，未完成动作继续保留。
