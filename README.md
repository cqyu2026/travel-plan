# travel-plan

中文旅行规划与手机手册 Skill，当前版本 **0.1.2**。

从出游需求开始，逐步形成可讨论的旅行计划；计划确认后整理交通、酒店、门票和预约待办，再根据订单与攻略核验安排。需要时生成可离线阅读的单文件 HTML 旅行手册。

## 文件

- [`travel-plan/SKILL.md`](travel-plan/SKILL.md)：技能入口、规划流程和订单核验规则。
- [`travel-plan/references/web-handbook.md`](travel-plan/references/web-handbook.md)：网页制作、隐私、交接、部署和验证要求。
- [`travel-plan/assets/travel-handoff.md`](travel-plan/assets/travel-handoff.md)：跨平台接续模板。
- [`travel-plan.zip`](travel-plan.zip)：仅含上述三个技能文件的导入包。

## 使用

下载 `travel-plan.zip`，或取得完整的 `travel-plan/` 文件夹，按所用工具的技能导入方式安装。保留文件夹结构，不能只复制入口文件而遗漏引用。

示例请求：

> 用 travel-plan 帮我规划上海到苏州的三天旅行。两位成人、一位6岁儿童，高铁往返，午休优先。先讨论路线，不制作网页。

> 我已经确认计划，按这些订单检查时间冲突，并更新剩余购买与预约待办。

> 按确认的计划制作离线 HTML，保留未预约状态，不需要天气和地图，也不要发布。

技能可供 Codex 与 WorkBuddy 按实际环境能力执行。只要规划或审核时不会自动制作网页；只要 HTML 时不会自动公开发布。网页发布仍需明确的目标与操作条件。

## 主要边界

- 初步规划不要求订单齐全，已有计划和订单从当前阶段接续。
- 购票、预约、核验与模拟标记分别保留；已购门票不等于已预约演出。
- 动态信息需查证适用日期，来源冲突或缺少依据时保留待核实。
- 不自动购票、付款、预约或创建监控。
- 公开 HTML、离线交付和交接材料不包含原始订单、确认号、证件号、二维码或私人联系方式。
- 新建与更新网页先检查已有文件，正文不依赖外部资源；天气和导航属于联网增强。
