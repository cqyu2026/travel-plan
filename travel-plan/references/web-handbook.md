# 旅行手册网页与部署规范

仅在制作、跨平台交接、修改网页或部署时读取。初步规划阶段不制作网页；完整流程在用户确认计划后随购买预约清单生成首版手册，核验订单并调整安排后同步更新。同一阶段交付实际 HTML 文件，首次公开发布仍需明确授权；已有公开页面默认与本地文件同步更新，除非用户明确要求不同步；用户明确限定不制作网页时遵守其范围。

## 单文件与离线

交付一个 `index.html`，HTML、CSS、JavaScript、SVG 和必要视觉资源内置。正文显示不依赖外部脚本、样式、字体、图片或 CDN；优先原生 HTML/CSS/JS，避免框架、大图和无用媒体。新建前检查目标目录，已有手册按用户范围修改，不直接覆盖；目标 index.html 与任务无关时使用新的明确目录。新建时先创建一个可直接打开、包含标题、逐日行程和待办的最小文件；天气、地图和交互在该文件上增量完成。不要在创建文件前输出长篇设计、伪代码或实现过程。

用户保存的 HTML 应能独立离线阅读完整行程，包括各方案、订单状态、待办和贴士。公开网址需联网首次访问，不承诺未保存过的页面可断网首次加载。交付时同时提供可下载或保存的 HTML 文件。

天气更新和外部地图导航是联网增强，不是正文加载依赖。网络失败不能阻止行程渲染。网页中的公开源码、内置数据、隐藏内容和注释也都受隐私规则约束，不只是屏幕上可见的文字。

## 页面结构

以下为完整手册的默认布局。用户明确要求简版、纯离线或不需要天气/地图时按其范围裁剪，不创建空模块，不因可选服务不可用而阻塞交付。时间不精确时展示日期或时段，不为倒计时补造时刻。

| 顺序 | 内容与行为 |
|---|---|
| 1. 此刻关注 | 当前方案正在进行的活动或下一事件、大号天/时/分/秒倒计时，每秒更新；确认全部活动结束且没有后续安排时显示行程结束 |
| 2. 目的地天气 | 当前行程涉及的目的地，每屏一个城市，只展示目的地当地当天天气状况与体感温度，保留城市、日期和数据更新时间 |
| 3. 总览地图 | 内置手绘感 SVG，按天用不同颜色画路线，标注每晚住宿；示意路线明确为示意，不伪装成精确道路导航 |
| 4. 出行前待订购与预约 | 按交通、酒店、门票等分组展示尚未完成的购买和预约，写明日期、渠道、窗口、前置条件与备选；完成对应动作后移除该待办，已确认订单信息融合到逐日行程；无待办时不保留空模块 |
| 5. 逐日行程 | 左侧时间、右侧内容，融合已确认交通、住宿、门票和预约的必要时间、准确地点、票种权益及状态，保留核验标记；未完成的购票与预约节点关联上方待办；每天可展开当日路线图，提供地点和按序导航入口 |
| 6. 待办与贴士 | 纯列表，不用浏览器各自存储完成状态的勾选框；只保留与当前方案有关的有效提醒 |

“此刻关注”保留原有样式和行为；修改现有手册时不因本次调整重新设计该模块。天气、总览地图、出行前待订购与预约均排在逐日行程之前。购票与预约分别完成和移除，未完成的预约、退款及待核实事项不能随已购信息一起消失；不在底部重复列出上方已有待办。

有多方案时提供名称明确的切换控件，当前方案始终可见。无需多方案的行程不创建空切换器。不能只隐藏时间轴而遗漏倒计时、地图或相关待办的切换。

## 时间与唯一事实来源

在 HTML 内使用一份当前行程数据，以稳定的事件标识关联时间轴、倒计时、地图和预约状态，避免同一班次时间在多个手写数组中漂移。不为单页引入数据库或通用状态框架。公开规则保留对应来源链接和核实日期，订单来源只用脱敏说明，不附私有订单链接。订单卡片和待办引用同一事项的时间、购票、预约与核验状态，不另外手写副本；计划调整后检查所有引用。用户文字与提取字段用 textContent 等文本接口渲染，确需插入 HTML 时转义，不将资料中的标签或脚本作为代码执行。

事件时间包含完整日期与明确时区/偏移。跨时区行程保存各事件发生地时区；涉及夏令时时，按该日期正确换算，不能使用全年固定偏移代替。显示时标注当地日期、时间与时区，倒计时以绝对时间计算，不依赖查看者设备时区解析无偏移的日期字符串。

跨夜活动明确起止日期，不将前晚 22:30 的开始写成次日晚开始。已知开头但没有准确时间的活动不虚构秒级倒计时；可显示待定并寻找后续有明确时间的事件。

持续活动按起止时间判断是否进行中；最后一段返程尚未抵达时显示返程中及已知抵达时间，不能因为没有未来开始事件而提前显示结束。结束时间或后续活动时间未知时显示待核实，不将缺少时间等同于行程完成。每次时钟刷新都根据当前时刻重新判断待开始、进行中和已结束；不能只在事件标题变化时刷新状态，避免同一活动开始后标签仍为“下一事件”。状态变化时同步可访问名称，结束后清除旧倒计时的文本与 aria-label。

## 天气与导航

天气使用制作时验证可用且允许当前用途的服务，不硬编码“永久免费”“全球可用”等未经验证的服务承诺。检查浏览器请求、跨域限制、返回格式、时区和单位。不能将私有 API 密钥嵌入公开 HTML；若服务必须使用私密凭证，不为此擅自增加后端，改选可用服务或说明阻碍。

需要天气模块时，默认加载时刷新天气、每 30 分钟更新并支持手动刷新，显示数据更新时间。天气内容只保留目的地当地当天的天气状况（如晴、雨）和体感温度，不另列实际温度、未来预报、湿度等字段。城市、当地日期和数据更新时间用于说明适用范围，不把当天天气当成未来出游日预报。

天气容器每页只显示一个城市，手势横向滑动与圆点切换。默认每 5 秒轮播；提供暂停/播放，用户手势操作或键盘聚焦后暂停，主动恢复后才继续；系统减少动态效果时不自动轮播。内容不得溢出页面或卡片重叠。加载、失败、单城市时不启动多城市轮播。

失败时保留正文并说明天气不可用；有成功缓存时可以显示，但必须注明缓存时间，不能显示为实时。山地可使用可获得的区域预报并标明代表范围，不把县城气温等同于山顶温度。

每个地点使用核实的名称、地址或坐标生成 Apple 地图链接，检查目标没有同名歧义。制作时根据官方支持情况验证全天多点路线；不支持就展示有序分段导航，不用只含起终点的链接冒充多点路线。无 Apple 地图的设备保留可读地址和可用网页入口，不承诺所有平台都能唤起 App。

## 移动端、视觉与公开内容

默认跟随设备浅色/深色模式；采用系统字体、明确层级、可读字号及足够触控面积。至少检查 320、390、768 像素视口，正文不发生页面级横向溢出；天气内部横向切换不影响整页宽度。可交互控件有文字或可访问名称，键盘能够展开路线、切换方案和操作天气。

禁止公开确认号、证件号、房间号、二维码、原始订单截图和私人联系方式，同行人默认代称。商家公开电话和酒店名称、地址可以使用，但需核实。离线文件、公开 HTML 源码与交接材料同样遵守该边界。

页面永远是当前终稿：不显示修改日志、版本说明或内部讨论，不残留被替代的班次和方案。必要的待购、待预约、待核实状态和数据源更新时间仍要显示。

## 部署分流

### WorkBuddy 全程实施

直接在当前任务完成已要求的网页制作或更新并检查，交付 HTML 文件与验证结果。首次公开发布需明确授权；已有公开页面默认同步更新本地 HTML 与公开页面，除非用户明确要求不同步到公开页面，不重复询问是否同步。不输出交接包，也不让用户重新复制同一任务的内容。使用环境真实提供的部署工具和返回地址，不沿用案例中的域名或猜造发布成功信息。

### 跨平台接续

仅此场景使用 `assets/travel-handoff.md`。填入最新完整计划、事实、来源和所有必要网页要求，使接手方不需要本地技能文件或原始聊天。已有 HTML 时附文件；更新时可另附简短变更范围，但变更说明不进入公开页。没有现成传输能力时交由用户粘贴/上传，不自动向外发送。

### 域名与托管

有域名时明确目标域名或子域名、托管平台、现有部署方式和已具备的操作权限。只有域名不等于已能托管；缺少托管条件时列出必要选择及用户步骤，先完成可离线交付的 HTML。不要在 Skill 中写死供应商或未经验证的部署命令。

无域名时由 WorkBuddy 发布；其他环境没有 WorkBuddy 部署能力则提供交接材料，不静默改用另一家托管平台。普通规划请求不自动授权修改 DNS 或发布；已经明确要求部署且路径明确时直接完成授权范围内的工作，不重复索取泛泛许可。

发布文件入口为 `index.html`，公开地址应直接打开手册，不是目录列表、本地端口、仅作者可见的预览、需登录下载页或依赖 App 的链接。需要用户操作时一次性列出操作、目的和是否必须使用电脑。

## 验证与交付

按实际产物验证，不能仅用“有某段代码”或 HTTP 200 代替运行检查：

1. 检查完整 HTML 与内置数据中的敏感信息、旧订单值、重复内容；核对实际存在的全部方案、事件和住宿。检查待核实内容未在网页变成确定事实；已购但待预约的动作仍在待办。
2. 运行页面，检查 JavaScript 错误、方案切换、下一事件选择，以及最后一项活动开始前、进行中、结束后的状态；让同一已打开页面跨过开始和结束时刻，不只分别重载三个时刻。未知时间不应误报结束。
3. 在不同设备时区模拟查看同一绝对时刻，倒计时结果应相同，当地时区标签应正确；包含跨夜样本。
4. 验证窄屏布局、手势和键盘操作、浅深色、天气成功/失败/缓存以及真实地图目标。无法实测 App 唤起时如实标注限制。
5. 用保存的 HTML 断网打开，检查完整正文和各方案仍可访问，不依赖首次联网下载资源。
6. 已有公开页面的更新，除用户明确要求不同步外，核对本地文件与公开页面均为本次最新内容；同时检查已打开的旧页面普通刷新和未登录新会话访问，避免只核对本地文件。首次部署后也以未登录方式打开真实公开网址，检查首页、手机版及本次变更后的具体内容。返回最新验证结果，不以响应码或字节数一致推断内容正确。

仅验证当前范围实际包含的模块，不适用项标不适用，不宣称已通过。不能运行浏览器时交付文件和静态检查结果，并明确运行未验证；如 file:// 受限且环境允许，可只对交付目录启动本机预览服务验证，结束后关闭；本机预览不算公开部署。

能修复时完成修复再交付；遇到账号、权限或服务故障，分别报告本地文件和公开页面的实际更新状态、具体阻碍和必要用户操作，不反复切换未知域名或宣称已发布。尽量复用原网址，变化时明确告知。

以上是实际网页制作阶段的验收要求；仅创建 Skill 文件时不能声称已通过这些网页或部署测试。
